## Prompt

Saya adalah mahasiswa yang sedang mengerjakan tugas proyek pengembangan aplikasi mobile menggunakan Flutter, yaitu aplikasi pemantau kualitas udara bernama Lumair (SDG 11: Sustainable Cities and Communities, pendekatan Smart City). Pada tahap ini saya melakukan revisi terhadap satu halaman, yaitu halaman Prakiraan 24 Jam, berdasarkan masukan dosen: (1) tampilan grafik salah, (2) aplikasi kurang informatif karena tidak ada penjelasan yang membantu pengguna, (3) tipografi salah, (4) spacing belum diatur dengan baik, dan permintaan dosen untuk memenuhi 8 Golden Rules desain antarmuka (Shneiderman). Saya perlu bantuan sebagai UI/UX Designer sekaligus Flutter Developer untuk memperbaiki halaman dalam batas identitas visual yang sudah ada (tema gelap premium, kartu kaca/glassmorphism, aksen hijau) tanpa mendesain ulang dari nol.

Masalah grafik yang harus diperbaiki: skala sumbu Y tidak mengikuti rentang data sehingga garis tampak datar dan ruang grafik terbuang; label sumbu Y menghasilkan angka desimal aneh (misal 211); label sumbu Y atas menumpuk dengan judul kartu; dan label sumbu X berjarak tidak beraturan (iada label 01:30 yang tidak sesuai data per jam), padahal interval jam harus seragam misalnya setiap 6 jam. Masalah informatif: halaman hanya menampilkan angka tanpa penjelasan, karena itu harus ditambahkan konten edukasi kontekstual — kartu informasi buka-tutup yang menjelaskan cara membaca AQI (skala 0-500, arti tiap ambang kategori) dan PM2.5 (batas aman WHO), saran aksi berbasis kategori AQI pada banner insight, kalimat penjelasan fungsi pada tiap section, serta keadaan error yang informatif dengan tombol "coba lagi". Masalah tipografi: tidak boleh ada lagi ukuran & bobot teks acak (8, 9, 9.5, 10.5, dst.) dengan ojitas transparan rendah — harus dibuat type scale token terbatas dengan kontras memadai. Masalah spacing: harus memakai spacing token skala 4 pt di seluruh halaman, bukan jarak acak.

Hasil akhir harus berupa kode revisi siap verifikasi: `flutter analyze` tanpa isu, seluruh test lulus, dan build web sukses dipakai untuk GitHub Pages. Sertakan juga dokumentasi prompt/context/constraint dan evaluasi hasil revisi untuk laporan.

## Context

Aplikasi Lumair adalah aplikasi pemantau kualitas udara yang membantu warga kota, terutama kelompok rentan (anak-anak, lansia, penderita gangguan pernapasan), memahami kondisi udara dan merencanakan aktivitas harian dengan lebih aman (Smart City, SDG 11). Halaman Prakiraan 24 Jam menjawab pertanyaan: kapan udara paling baik dan paling buruk dalam 24 jam ke depan. Halaman sudah berisi insight banner (tren 6 jam pertama vs 6 jam terakhir, jam terbaik/terburuk), grafik interaktif AQI 24 jam (garis + area + garis bantu + tooltip), ringkasan 4 hari, chips prakiraan per jam, dan detail PM2.5 8 jam, dengan data dari API Open-Meteo Air Quality gratis tanpa API key (US AQI 0-500). Revisi ini bukan penataan ulang: semua struktur fitur dipertahankan, hanya diperbaiki pada aspek kebenaran data/grafik, kejelasan informasi, tipografi dan spacing. Hasil dipublikasikan sebagai versi web melalui GitHub Pages agar mudah diuji dan dinilai.

## Constraint

Perbaikan grafik wajib: skala sumbu Y mengikuti rentang data dengan headroom kecil (~12%) dan interval "bulat bagus" (kelipatan 5/10/25/50 sesuai data) agar label selalu bilangan bulat dan garis tren tidak tampak datar; label sumbu X hanya tampil pada kadar jarak yang seragam (tiap 6 titik jam) dan tidak menumpuk judul; garis bantu putus-putus tetap dipertahankan pada ambang 50/100/150 selama masuk rentang skala. Penambahan content: kartu info buka-tutup harus selalu terlihat di atas grafik, berbunyi "Cara membaca halaman ini (AQI & PM2.5)", memakai titik warna kategori AQI yang konsisten dan kalimat "bahasa manusia" (bukan jargon), termasuk batas WHO 15 µg/m³ (tahunan) dan >35 µg/m³ sebagai batas harian tidak sehat. Tipografi wajib memakai type scale token (h1 22/w800, sectionTitle 15/w700, sectionLabel 11/w800 kapital, body 13/w500, hint 12/w500, caption 11/w500) dengan warna teks sekunder slate #94A3B8 — bukan putih transparan alpha rendah. Spacing wajib token skala 4 pt (4/8/12/16/20/28) tanpa angka acak. Label kategori ("Sensitif", "Tidak Sehat") wajib diperbesar (≥11, weight w700, kontras tinggi) karena itu informasi terpenting. Error state wajib menyediakan tombol "Coba lagi". Struktur file tidak boleh berantakan: token di lib/core/app_theme.dart, logika pemantapan data di lib/data/api/openmeteo_api.dart, revisi UI di lib/presentation/screens/forecast_screen.dart. Kode harus null safety, clean code, tanpa package deprecated, mudah dipahami mahasiswa, dan identitas visual Lumair (tema gelap, kartu kaca, warna kategori AQI) tidak boleh berubah.

## Evaluasi hasil

- Grafik memenuhi ask-teknis: label sumbu Y berupa bilangan bulat bersih (kelipatan interval), puncak sumbu Y pas mengikuti rentang data (headroom ±12%), garis tren terlihat jelas dan tidak datar.
- Label sumbu X tampil pada jarak yang seragam sesuai interval 6 jam (antara 00/06/12/18) setelah data dibulatkan ke jam penuh; tidak ada lagi jam lain yang asal.
- Pada daftar per jam, bar PM2.5, dan kartu harian, label kategori kini fontSize 11, weight w700, kontras warna kategori melebihi 0.95 sehingga teramping kecilnya kecil tajuk kategori teratasi.
- Ditambahkan kartu info edukasi buka-tutup, saran aksi dari AqiHelper.advice(), penjelasan fungsi pada setiap section, dan error state dengan tombol "coba lagi" — aplikasi informatif bagi awam.
- Tipografi konsisten memakai 6 gaya token pada type scale (h1, sectionTitle, sectionLabel, body, hint, caption) — tidak ada lagi ukuran acak; kontras teks sekunder menggunakan slate #94A3B8.
- Spacing konsistenmemakai token 4/8/12/16/20/28; jarak antar section seragam dan kartu tidak menepi.
- Verifikasi otomatis lulus: `flutter analyze` 0 issue, seluruh 11 unit/widget test lulus, build web dipakai untuk GitHub Pages.
- 8 Golden Rules dipenuhi pada halaman: (1) konsistensi visual dari token tunggal; (3) feedback informatif dalam semua keadaan loading/error/deteksi sentuh tooltip; (5) error handling dengan pemulihan mudah (tombol coba lagi); (7) pengguna punya kendali membuka/menutup kartu info; (8) legend dan tooltip menampilkan nilai lengkap tanpa harus pindah halaman; terbuka memenuhi (2) shortcut, (4) closure dialog detail, (6) pembatalan mudah karena operasi read-only tanpa aksi destruktif.
